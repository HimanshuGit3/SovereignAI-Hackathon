# API Specification

For the frontend team. Base URL during development:

    http://192.168.59.10:8080

Interactive docs generated by FastAPI: `/docs` (Swagger UI). Use it to
try any endpoint live before writing code against it.

CORS is open to all origins, so a React dev server on any port works.

---

## GET /api/health

Poll on mount and every 30 s for the status bar.

```json
{
  "status": "ok",
  "inference_endpoint": "http://10.0.2.2:11434",
  "inference_reachable": true,
  "models": [
    {"id": "general", "name": "qwen3.5:2b-q4_K_M", "role": "general", "present": true}
  ],
  "sandbox_available": true,
  "tools": ["read_document", "list_files", "run_python", "..."],
  "timestamp": "2026-09-13T02:40:11"
}
```

`status` is `"ok"` or `"degraded"`. Degraded means Ollama is unreachable —
show a red banner; nothing else will work.

## POST /api/route

Routing decision only. No model call unless the request is ambiguous.
Useful for showing the user which model will handle their task before
they commit.

Request:

```json
{"task": "Draft an approval note", "attachments": []}
```

Response:

```json
{
  "task_type": "document",
  "model_id": "general",
  "model_name": "qwen3.5:2b-q4_K_M",
  "reason": "document signals score 8.0 (3 matched)",
  "method": "deterministic",
  "confidence": 1.0,
  "routing_latency_ms": 1
}
```

`task_type` is one of `chat`, `document`, `code`, `vision`, `embedding`.
`method` is `deterministic` (0–1 ms) or `llm` (~400 ms).

## POST /api/task/stream

**Primary endpoint. Use this, not `/api/task`.** Server-sent events, one
per agent step, so the UI shows progress instead of a spinner.

Request:

```json
{"task": "Read data/samples/inspection_report.png and summarise it",
 "attachments": []}
```

Event stream. Each line is `data: {json}\n\n`. Switch on `type`:

**1. `routing`** — arrives first, same shape as `/api/route` plus a type field.

**2. `step`** — one per agent action.

```json
{
  "type": "step",
  "n": 1,
  "kind": "tool",
  "tool": "read_document",
  "ok": true,
  "arguments": {"path": "data/samples/inspection_report.png"},
  "observation": "MANGALORE REFINERY - EQUIPMENT INSPECTION REPORT...",
  "content": "",
  "elapsed_ms": 1105,
  "model": "qwen3.5:2b-q4_K_M"
}
```

`kind` is `"tool"` or `"final"`. For `final`, `content` holds the answer
and `tool` is empty. Render tool steps as collapsible cards (arguments and
observation inside) and the final step as the answer block.

**3. `done"`** — last event.

```json
{
  "type": "done",
  "steps": 3,
  "tool_calls": ["read_document", "create_word_document"],
  "orchestrator_model": "qwen3.5:2b-q4_K_M",
  "delegate_models": [],
  "tools_offered": ["read_document", "list_files", "..."],
  "artifacts": ["outputs/approval_note.docx"],
  "total_ms": 7025,
  "stopped_reason": "model returned a final answer",
  "answer": "I have created the approval note..."
}
```

**4. `error`** — `{"type": "error", "error": "TypeError: ..."}`.

React consumption. `EventSource` cannot send a POST body, so use fetch
with a stream reader:

```js
const res = await fetch(`${API}/api/task/stream`, {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({task, attachments: []})
});

const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = "";

while (true) {
  const {value, done} = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, {stream: true});
  const parts = buffer.split("\n\n");
  buffer = parts.pop();                 // keep the incomplete tail
  for (const part of parts) {
    if (!part.startsWith("data: ")) continue;
    const event = JSON.parse(part.slice(6));
    handleEvent(event);                 // switch on event.type
  }
}
```

The `buffer.pop()` line matters: events can split across chunks.

## POST /api/task

Same input, no streaming. Returns everything at once after 7–25 s. Only
use it where streaming is impractical.

## POST /api/workflow

The flagship demo path. Four fixed stages, more reliable than the
open-ended agent.

Request:

```json
{
  "workflow": "inspection_to_approval",
  "document_path": "data/samples/inspection_report.png",
  "output_filename": "approval_note.docx"
}
```

Response (~12 s):

```json
{
  "workflow": "inspection_to_approval",
  "stages": [
    {"n": 1, "name": "ingest document", "detail": "ocr in 321 ms, 873 chars",
     "ok": true, "elapsed_ms": 321},
    {"n": 2, "name": "extract structured fields",
     "detail": "P-101A | HIGH | 4 findings", "ok": true, "elapsed_ms": 2636},
    {"n": 3, "name": "consult SOPs",
     "detail": "top 0.801 [SOP-MECH-014...]", "ok": true, "elapsed_ms": 7958},
    {"n": 4, "name": "draft approval note",
     "detail": "Created Word document...", "ok": true, "elapsed_ms": 1898}
  ],
  "artifacts": ["outputs/approval_note.docx"],
  "summary": "Processed inspection_report.png: P-101A (HIGH criticality)...",
  "total_ms": 12821,
  "failed": ""
}
```

Not streamed. Show a four-stage progress indicator and poll nothing —
just await the response.

`GET /api/workflows` lists available workflows.

## Knowledge base

    GET  /api/kb/status    -> {"total_chunks":20,"documents":[...],
                               "embed_model":"nomic-embed-text"}
    POST /api/kb/reindex   -> re-reads data/kb/, returns new stats
    POST /api/kb/ask       body: {"task":"what is the seal lead time"}

```json
{
  "question": "what is the seal lead time",
  "confident": true,
  "top_score": 0.820,
  "answer": "The lead time for a standard cartridge seal is 21 days from purchase order [CORR-2026-0318_vendor_seal_supply.md #3].",
  "sources": [
    {"citation": "[CORR-2026-0318_vendor_seal_supply.md #3]",
     "score": 0.82, "source": "data/kb/CORR-2026-0318_vendor_seal_supply.md",
     "excerpt": "..."}
  ],
  "elapsed_ms": 7362,
  "model": "qwen3.5:2b-q4_K_M"
}
```

`confident: false` means retrieval scored below the 0.58 floor and no model
was called at all. Render those in grey with a low-confidence tag. Do not
present them as organisational requirements.

Always render the sources list. The citations are the point of the feature.

## Files

    GET  /api/files
      {"samples":[{"name":"inspection_report.png",
                   "path":"data/samples/inspection_report.png",
                   "size":68761,"area":"sample",
                   "modified":"2026-09-12T23:17:32"}],
       "uploads":[...], "outputs":[...]}

    POST /api/upload        multipart/form-data, field name "file"
      -> {"ok":true,"name":"x.pdf","path":"data/uploads/x.pdf","size":12345}

    GET  /api/download/{filename}
      -> the file itself. Plain <a href> works for generated .docx.

Use `path` from `/api/files` as `document_path` for a workflow, or place it
in `attachments` for a task.

## Sovereignty monitor

    GET  /api/monitor/egress
    POST /api/monitor/egress/reset      clear before a demo run
    POST /api/monitor/capture/start     begin tcpdump capture
    POST /api/monitor/capture/stop      -> summary plus a "report" text block
    GET  /api/monitor/classify?host=8.8.8.8

```json
{
  "total_requests": 10,
  "external_count": 0,
  "sovereign": true,
  "by_classification": {"LOCAL": 0, "PRIVATE": 10, "EXTERNAL": 0},
  "destinations": ["10.0.2.2:11434"],
  "events": [{"ts": "...", "host": "10.0.2.2", "port": 11434,
              "classification": "PRIVATE", "status": 200, "elapsed_ms": 4225}],
  "report": "...pre-formatted text block..."
}
```

Poll `/api/monitor/egress` every 5–6 seconds. This panel matters more than
anything else on screen during judging: a persistent badge reading
**EGRESS — 0 EXTERNAL** in green, flipping red if `external_count > 0`.

## Suggested screens

| Screen | Contents |
|---|---|
| Workbench (main) | Task input, preset chips, live step trace from the SSE stream, download button per artifact |
| Sovereignty | Egress panel, destinations, classification counts, large green/red verdict |
| Knowledge base | Ask a question, show the answer with citation chips and scores. Include one question the SOPs cannot answer, to show the refusal |
| Models | Registry cards, VRAM residency, routing preview from `/api/route` |

## Timings to design around

| Operation | Typical |
|---|---|
| Routing | 0–1 ms deterministic, ~400 ms via LLM classifier |
| Simple task | 1–6 s, usually 2 steps |
| Flagship workflow | ~12 s, 4 stages |
| Agent with tools | 7–25 s, 2–4 steps |
| KB question | 5–9 s |

Nothing here is instant. Every action needs a visible progress state, which
is why the streaming endpoint exists.

`web/index.html` is a working reference implementation — plain HTML, no build
step. Read it for the stream-parsing logic before writing the React version.
